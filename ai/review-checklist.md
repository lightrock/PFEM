# Review Checklist

Before accepting a change, check:

- Does it use neutral deployment-shape language?
- Does it keep evidence, observations, findings, alerts, packages, rollups, and reports separate?
- Does it preserve lineage for derived objects?
- Does it keep adapters out of policy decisions?
- Does it keep profiles as configuration, not product forks?
- Does it avoid UI code becoming operational truth?
- Does it include samples, schemas, or tests when changing contracts?
- Does it explain any new capability or boundary?
